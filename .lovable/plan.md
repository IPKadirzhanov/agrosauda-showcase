# Аудит сайта Agrosauda: найденные баги и проблемы

## 1. Критично: витрина не показывает реальные объявления

Проверено по коду: страницы «Агро Шоп» (`/agro-shop`, `/marketplace`), «Объявления» (`/classifieds`), категории (`/category/...` и SEO-слаги), главная и «Избранное» берут товары из локального файла `src/data/mockData.ts`, а не из базы.

Последствия:
- Пользователь публикует объявление → админ одобряет → объявление **нигде не появляется** на сайте.
- «Избранное» работает по демо-товарам, реальные товары туда не попадают.
- Продвижение через Freedom Pay оплачивается, но ТОП-объявление негде показать (страницы не читают `promoted_until`).

Что сделать: перевести витрину, категории, главную и избранное на реальные данные из базы (только `status = 'approved'`), с сортировкой продвинутых объявлений вверх, фильтрами по категории/региону/цене и корректным пустым состоянием. Демоданные оставить только как запасной вариант, если база пуста.

## 2. Безопасность базы (сканер, 2 критических + 6 предупреждений)

- **Телефоны пользователей открыты всем** — таблица `profiles` доступна на чтение анонимным посетителям (утечка телефонов и имён).
- **Платежи можно подделать** — `broker_payments` разрешает INSERT/UPDATE любому пользователю, включая анонимного (можно вписать себе «оплачено»).
- `broker_deals` виден всем, а не только участникам сделки.
- `ai_messages` можно записывать в чужие диалоги.
- Загрузка видео в хранилище не привязана к папке пользователя.
- Отключена защита от утёкших паролей.
- SECURITY DEFINER функции доступны на исполнение анонимам.

Что сделать: миграция с ужесточением политик (profiles — только свой профиль/авторизованные, платежи — только сервисная роль, сделки — только участники, сообщения — проверка владельца), исправление политики загрузки, включение защиты паролей и ограничение EXECUTE.

## 3. Дублирующиеся H1 (SEO)

На страницах `SellPage`, `CategoryPage`, `ProductDetailPage`, `BlogArticlePage`, `FavoritesPage` по два тега `<h1>`. Должен быть один. Лишние заменить на `<h2>`/`<p>`.

## 4. Прочие недочёты

- Часть изображений без `alt` — минус к SEO и доступности.
- Страницы «Субсидии», «Обучение», «Новости» показывают демо-контент, хотя в базе есть таблицы `subsidy_programs`, `courses`, `news_articles` (заполнены они или нет — надо проверить перед переключением).
- Нет уведомления продавцу о результате модерации (одобрено/отклонено) — пользователь не понимает, что стало с объявлением.
- Нет страницы «Мои избранные» на реальных данных и счётчика непрочитанных заявок.

## Порядок работ

1. Витрина на реальные данные (пункт 1) — самое заметное для пользователей.
2. Миграция безопасности (пункт 2).
3. SEO-правки: H1, alt (пункты 3–4).
4. Уведомления о модерации.
